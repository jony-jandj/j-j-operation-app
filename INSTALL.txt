J&J WORK & PAY UPDATE — INSTALL ORDER

This is an update to the existing jony-jandj/j-j-operation-app repository, not a replacement repository. Keep all other existing files, including homeowner/customer scripts, icons, selection data assets and authentication configuration.

1. Export the current app backup and retain a copy of the repository's current index.html and service-worker.js.
2. In your existing Supabase project, paste WORK_PAY_SETUP.sql into the SQL editor and run it. This creates separate staff-only payment storage. It does not update existing job, selection or estimate records. It expects your existing public.profiles table with admin/pre_approver/final_approver roles.
3. In the GitHub repository root, upload/replace ONLY these four files together:
   index.html
   work-pay.js
   estimate-full-parser.js
   service-worker.js
4. Wait for GitHub Pages to finish, then refresh the app. Sign in as staff and click Payments. A successful connection shows your actual approved P.O.s under Work awaiting completion.
5. Verify one real P.O.'s amounts and description before recording real completion or payment data. Older approved P.O.s are not automatically treated as completed or paid. Enter their actual completion dates. Record only payments actually made.

Normal use:
- P.O. Splits: Connect Work & Pay, then edit a draft P.O. Use Sub for contractor percentage of builder cost (75% default), or choose crew members. Undo approval before changing an approved unpaid split.
- Existing splits and amounts are retained on installation. New P.O.s start with one unnamed 100% crew allocation. Add member redistributes the crew allocation evenly, maximum four. Crew base remains 60% of builder cost.
- Payments: Work complete records a fixed payout/description snapshot. Ready to pay records partial/full payments and permits multiple outstanding P.O. lines for the same payee.
- Payday is selected explicitly, biweekly Fridays anchored to September 11, 2026. Completion-date reporting periods are separate from payroll assignment. Weekly and biweekly report start dates are Sundays; monthly/yearly reports use calendar boundaries.
- Subs Summary shows assigned scope per company/job/P.O.; draft scope is not a recorded payment. In-house Summary uses actual recorded completion dates.
- Both summaries offer P.O. description popups and printable descriptions. Payment history can filter payee, job, status, method, date and reference.
- Use Export payment backup in Payments for the separate ledger. The old app backup exports job data; it does not include this separate ledger.

Important operating details:
- New payment writes require a cloud connection. Conflicting saves are rejected; refresh and review before trying again.
- Completed payout snapshots cannot be changed. Original payment records are retained; void a mistaken payment with a reason, then enter the correct record. Voiding a record does not reverse a bank transaction.
- No actual money is sent. This release does not upload receipt files, process payroll taxes, or include manager salary.
- No sample jobs, sample payments, or uploaded personal estimate contents are shipped.
- Imported report fields are retained, including pricing, margin and tax fields. Display hides Parent Group Description, Subgroup Description, Subgroup and Option Type. Missing values remain blank. Existing P.O. costs do not change when an estimate is imported or edited.
